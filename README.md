# Pear Liquid Glass — прототип с подключаемой базой

## Что готово
Адаптивный интерфейс, тёмная/светлая тема, профиль собеседника по нажатию, редактирование своего имени и описания, загрузка аватарки, вход и регистрация по логину/паролю, поиск пользователя по точному логину и личные сообщения. Без настроенной базы кнопка «Посмотреть демоверсию» работает локально; в деморежиме отправка сохраняется только в браузере, настоящие аккаунты и доставка сообщений отключены.

## Как включить настоящие аккаунты и переписку
Нужен ваш собственный проект Supabase. Без следующих шагов после загрузки на Vercel настоящие аккаунты НЕ заработают.

1. Создайте **новый** проект на supabase.com. Не используйте существующую базу: скрипт настраивает таблицы, хранилище и триггер для регистрации Pear.
2. Откройте SQL Editor и выполните весь файл `schema.sql` **один раз**. Он создаёт `profiles`, `messages`, RLS-политики и публичный bucket `avatars`.
3. В Authentication → Providers → Email включите вход по email и **выключите Confirm email**. Supabase поддерживает пароль с email, поэтому для входа по указанному логину проект использует внутренний технический адрес `логин@pear-login.example.com`. Этот адрес не принадлежит пользователю. Подтверждение почты и восстановление пароля не работают. Не отправляйте письма на этот адрес и не используйте эту схему для публичного продукта без переработки регистрации.
4. В Project Settings → API / Connect скопируйте Project URL и **publishable key** (или legacy `anon` key). Вставьте их в `config.js`. Никогда не помещайте `service_role` или secret key в сайт или репозиторий.
5. Загрузите все файлы из архива в GitHub. В Vercel импортируйте репозиторий, Framework Preset: **Other**, Build Command и Output Directory оставьте по умолчанию. Нажмите Deploy.
6. Создайте два аккаунта с разными логинами, откройте один в другом браузере/приватном окне. В каждом аккаунте нажмите `+` и найдите собеседника по точному логину. После первого сообщения диалог появится у другого пользователя при обновлении (автопроверка раз в 5 секунд).

Логин: 3–24 латинских символа, цифры или `_`; пароль — минимум 8 символов. Пользователь может менять имя, описание и фотографию в настройках. Фото ограничены 2 МБ и типами JPG, PNG, WebP.

## Важно о приватности и готовности
Это стартовый прототип, не защищённый production-мессенджер. Сообщения **не имеют сквозного шифрования** и доступны администратору проекта/провайдеру. Профили и логины видны зарегистрированным пользователям, а ссылки на фотографии публичны. Поиск по логину допускает обнаружение пользователей. Нет восстановления пароля, блокировки пользователей, антиспама, модерирования, подтверждения личности и полноценной защиты от злоупотреблений; бесплатные лимиты Supabase также могут помешать частым регистрациям. Настройте это и проведите аудит безопасности перед публичным запуском. SQL/RLS и реальная регистрация требуют проверки на вашем проекте: без ваших ключей и базы полноценное сквозное тестирование невозможно. История загружается максимум до 500 сообщений на пользователя; полная пагинация не реализована.

Используется Supabase JS через CDN jsDelivr, поэтому для входа и работы настоящей версии требуется интернет. Исходный код не содержит ваших ключей и не хранит пароль пользователя самостоятельно; авторизация выполняется Supabase Auth.
